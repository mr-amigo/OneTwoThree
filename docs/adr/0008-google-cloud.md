# 0008. Spry on Google Cloud: a service for every piece

Status: accepted, 2026-11-25 (configuration written and validated; not applied, see "Consequences")

## Context
Lab 9 asks what it would take to run the same system on a second cloud. Spry runs on AWS:
- frontend: S3 + CloudFront;
- API: FastAPI on Lambda with a function URL;
- database: Aurora Serverless v2 PostgreSQL, 0–1 ACU, pausing when idle;
- sign-in: Cognito with Google;
- weekly report: EventBridge Scheduler → SQS → Lambda → S3 → Lambda → SES;
- agenda parser: a Lambda calling the OpenAI API, with Claude on Bedrock ready.

Infrastructure is Terraform (Lab 7) and CloudFormation. The core that makes the app usable is the
frontend, the API and the database. That core moves first. The rest is decided row by row.

## Decision

| Spry on AWS | On Google Cloud | Decision for this project |
| --- | --- | --- |
| S3 + CloudFront (Free plan) + WAF | Firebase Hosting | **Replace.** Free plan, CDN and certificate included. `/api/**` is rewritten to Cloud Run, so the SPA and the API share one origin and need no CORS (`gcp/firebase.json`). |
| Lambda + function URL, FastAPI | Cloud Run | **Replace.** The same Docker image as Docker Compose (`back/Dockerfile`, now listening on `$PORT`). The Lambda image and Mangum are not needed. Min instances 0, request-based billing. |
| ECR | Artifact Registry | **Replace.** Cleanup policy keeps the last 5 images, inside the 0.5 GB free tier. |
| Aurora Serverless v2 | Cloud SQL for PostgreSQL, db-f1-micro | **Replace with Cloud SQL, stopped when unused.** See "The database" below. |
| DynamoDB | Firestore | Not used: Spry has no DynamoDB table. |
| Cognito user pool + Google | Identity Platform | **Keep on AWS for now.** Cloud Run verifies Cognito ID tokens exactly as the Lambda does (the issuer's JWKS is reachable from Cloud Run). Moving users means migrating accounts and their `sub`s; Identity Platform's 50,000 free MAU is a later step. |
| EventBridge Scheduler | Cloud Scheduler | **Keep on AWS** (stretch). On GCP: one Cloud Scheduler job (3 free) calling a Cloud Run endpoint. |
| SQS | Pub/Sub (or Cloud Tasks) | **Keep on AWS** (stretch). Cloud Tasks is the closer match: a work queue with retries towards one Cloud Run endpoint. |
| S3 event → Lambda | Cloud Storage + Eventarc → Cloud Run | **Keep on AWS** (stretch). |
| SES | no Google service | **Keep SES.** See "E-mail". |
| Bedrock / OpenAI API | Vertex AI (Gemini, Claude in Model Garden) | **Keep the OpenAI API.** The parser is provider-neutral (`app/ai/llm.py`); a Vertex AI provider is one more class. The trial credit would not pay for Claude anyway. |
| SSM Parameter Store / Secrets Manager | Secret Manager | **Replace.** The database password is generated by Terraform (`random_password`) and read by Cloud Run from Secret Manager (6 versions free). |
| CloudWatch Logs | Cloud Logging | **Replace** (automatic for Cloud Run). |
| IAM roles | Service accounts + IAM roles | **Replace.** One service account per program: `meetings-api` (Cloud SQL client, reads one secret) and `meetings-deployer` (CI). Neither is the default compute account. No key files: application default credentials on a laptop, **Workload Identity Federation** for GitHub Actions (`gcp/wif.tf`), restricted to this repository by its numeric repository and owner IDs and to `main`. |
| Terraform aws provider | Terraform google provider | **`gcp/`**, separate from `infra/`, with its own state (key `gcp/terraform.tfstate`), so one plan cannot break both clouds. The APIs are enabled from Terraform. |

**The database.**

| Option | Latency | Bill (nobody uses it / office hours) | Code |
| --- | --- | --- | --- |
| Cloud SQL around the clock | ~1 ms from Cloud Run in the same region | $9.37 / $9.37 | none |
| **Cloud SQL stopped when unused** (`db_running = false`, or a scheduler that starts it for office hours) | same; the first request after a start waits ~1 min | **$1.70 / $3.55** | none |
| Firestore | ~10 ms per read | $0 / $0 at student traffic | rewrite of every repository and query: no joins, documents designed per screen |
| Keep Aurora on AWS, call it across clouds | +20–60 ms per query (us-central1 ↔ us-east-1), many queries per request | AWS bill as today + egress $0.12/GB from Google | none, but Aurora sits in a private VPC: it would need public exposure or a VPN, which is the opposite of Lab 4 |

Spry is relational (meetings, participants, a join table, owners, migrations). So it keeps
PostgreSQL. For a student project it runs Cloud SQL only when someone uses it. Firestore would make
an idle month free, but it costs a rewrite of the data layer. The cross-cloud database is ruled out
by its latency and its network exposure.

**E-mail.** Keep **Amazon SES** (sending is already verified, and it costs cents). Multicloud is
allowed. When the weekly report moves, its Cloud Run job calls SES with an IAM user's access key,
or with **SendGrid**'s API key. Either way the key lives in **Secret Manager** and is read by the
job's service account, never in the repository or an image.

**What we would not move.**
- **The agenda parser**: it calls the OpenAI API, so the cloud only hosts a function.
- **Sign-in, until the users can be migrated.** Every account is tied to a Cognito `sub`.
- **The weekly report**: it is event-driven glue built from five AWS services. Rebuilding it gives no
  user-visible gain until the database itself lives on GCP for good.

## Alternatives considered
- **Everything in one cloud plan.** Rejected: an error in one provider's resources would block or
  break the other cloud's apply, and the blast radius of every change doubles.
- **App Engine** instead of Cloud Run. Rejected: Cloud Run runs the existing container unchanged.
- **AlloyDB.** Aurora-like and much larger; far beyond this project's size and budget.

## Consequences
- **The configuration is written and validated but not applied.** The Google Cloud free-trial signup
  for this project's account was refused by Google Payments on 25 November 2026 ("For your protection,
  a Google Cloud signup was denied"). The lab's no-account route is used:
  - `terraform init` and `terraform validate` in `gcp/` instead of `apply`;
  - the image run the way Cloud Run runs it, locally (`docs/lab9-runs/`).

  With a billing account it is `gcloud auth application-default login` →
  `terraform -chdir=gcp apply -var project_id=…` → push the image → `firebase deploy`.
- **Lock-in moved, not removed.**
  - Compute moved unchanged: the same image, now listening on `$PORT`.
  - Data moved unchanged: PostgreSQL to PostgreSQL, the same Alembic migrations.
  - The lock-in is in the managed services around them: Cognito, SES, SQS and Scheduler, and the
    IAM model.
- **Cost profile changes.** Aurora pauses, and Cloud SQL does not. An idle month goes from ≈ $0.55 to
  $9.37 unless the instance is stopped (see `docs/lab9-report.md`).
